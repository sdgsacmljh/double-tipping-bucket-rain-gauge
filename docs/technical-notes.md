# 技术说明

这份文档面向需要维护或继续开发项目的人，README 保留面向观众的项目介绍。

## 运行方式

页面使用 Vite 构建，Three.js 负责场景渲染、相机控制和模型加载。三维模型以 GLB 文件放在 `public/models/` 下，页面运行时直接加载它。项目没有后端服务，构建结果可以部署到支持静态文件的托管平台。

`vite.config.js` 使用相对资源路径，因此项目可以部署在 GitHub Pages 的仓库子路径下。GitHub Actions 工作流会安装依赖、执行生产构建，并把 `dist/` 发布到 Pages。

## 动画配置

动画相关配置集中在 `src/config.js`，控制器实现位于 `src/animation.js`。

- 页面优先播放 GLB 中名为 `Full_Demo` 的完整动画片段。
- 页面把动画划分为收集降水、翻斗导水、节流稳流、计量、磁控脉冲和累计读数六个阶段。
- 脉冲时刻由 `pulseTimes` 配置，雨量换算由 `rainPerPulse` 配置。
- 脉冲计数根据动画当前时间重新计算，暂停、继续、慢动作和重置不会造成重复累计。
- 当前完整演示约持续三十秒，包含五次脉冲，页面按每次 `0.1 mm` 更新读数。

修改动画阶段或读数规则时，优先调整 `src/config.js`，不要把同一组参数分散到多个业务文件中。

## 交互模块

`src/viewer.js` 负责场景、灯光、相机、自动旋转、触控操作和自适应取景。

`src/components.js` 负责点击拾取、部件映射、高亮、定位查看和内部观察。部件名称映射集中在 `componentInfo`，模型更新后如果出现部件无法识别，先检查 GLB 导出后的运行时名称，再补充映射配置。

内部观察通过临时调整指定外壳材质的透明度实现，退出模式时会恢复材质原状态。该功能只改变页面中的显示状态，不写回 GLB 文件。

## 模型更新

更新模型时，将新的 GLB 放入 `public/models/rain-gauge.glb`，确认文件包含可播放的完整动画，并检查动画名称、部件名称和辅助对象命名是否仍与配置一致。

如果浏览器缓存了旧模型，同时更新 `src/config.js` 中 `modelUrl` 的版本参数。完成模型替换后执行

```bash
npm ci
npm run build
```

然后在本地检查模型加载、动画播放、部件点击、内部观察和读数变化，再推送到 `main` 触发 Pages 部署。

## 统计接入

统计功能由 `src/analytics.js` 提供可插拔加载层，配置入口是 `src/config.js` 中的 `CONFIG.analytics`。目前代码兼容 Umami、Plausible、百度统计、51.la 和 Clarity。

互动事件由 `src/main.js` 统一记录，包括模型加载、演示开始与结束、暂停、慢动作、内部观察、自动旋转、部件查看和页面可见停留时间。没有配置对应服务时，不会加载该服务脚本。

统计接入应遵循服务商的公开埋点方式，避免把账号密码、访问令牌或其他私密凭据写入前端代码。浏览器启用 Do Not Track 时，统计脚本不会加载。

## 验证重点

每次发布前至少检查以下内容

- `npm run build` 成功完成。
- 在线页面可以加载 GLB，演示控制按钮在模型加载完成后启用。
- 旋转缩放、部件说明、慢动作、内部观察和视角恢复均可操作。
- 播放完整动画时，脉冲次数和累计雨量随阶段变化，重置后读数回到初始状态。
- GitHub Actions 的 Pages 部署工作流完成并生成可访问页面。

## 使用边界

当前项目用于结构和工作原理展示。模型中的水流、脉冲和读数属于科普演示设定，不能作为设备制造尺寸、计量检定结论或现场测量结果。
